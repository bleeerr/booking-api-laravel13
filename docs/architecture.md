# Architecture

Coworking Booking API — небольшое Laravel-приложение с Eloquent и HTTP API `/api/v1`. Бизнес-логика реализована непосредственно в контроллерах, Form Requests и Policies: отдельный service/repository слой не нужен для текущего объёма проекта.

## Компоненты

- **Auth:** Laravel Sanctum (Bearer tokens), роли `user` и `admin`.
- **Workspaces / Rooms:** администратор создаёт и редактирует, список коворкингов и активных комнат публичен.
- **Bookings:** пользователь создаёт `pending`, администратор подтверждает, пользователь или администратор отменяет допустимые бронирования.
- **Database:** PostgreSQL `timestamptz`, внешние ключи, проверки допустимых значений, exclusion constraint по комнате и временному диапазону.
- **Notifications:** Events → queued Listeners (`ShouldQueueAfterCommit`) → Mailables → Redis worker → `log` или SMTP.

## Правила бронирования

- `pending` и `confirmed` блокируют интервал; `cancelled` — нет.
- Интервалы полуоткрытые: `[starts_at, ends_at)`; смежные интервалы разрешены.
- Входные даты — RFC 3339 с обязательным `Z` или смещением, **без дробных секунд**; точность — одна секунда.
- Сервер считает стоимость в минимальных единицах валюты как `ceil(price_per_hour_minor * duration_seconds / 3600)` с защитой от переполнения.
- Нельзя бронировать неактивную комнату.
- При изменении статуса используется транзакция и блокировка записи (`lockForUpdate()`).
- PostgreSQL exclusion constraint `bookings_no_overlap` предотвращает двойное бронирование и при конкурентных вставках.

## API и права

Маршруты описаны в [`openapi.yaml`](openapi.yaml). Для ошибок API используется единая форма `error: {code, message, details}`. Авторизация на изменение сущностей реализована через Policies/Gates.

## Ограничения демо

Доступность комнаты — справочная проверка на текущий момент; создание бронирования отдельно защищено ограничениями PostgreSQL. Почтовая очередь имеет семантику повторных попыток, поэтому при сбое SMTP дублирование письма теоретически возможно.
